# Правила, которые сами не срабатывают — подмешано SessionStart-хуком

Канон проекта — `AGENTS.md`, и при расхождении прав он. Здесь — **то, что сессии забывают**:
правила, чей триггер — момент, а не задача. Кроме таблицы «момент → скил» все они стоят и в
каноне; хук не подменяет носителя, а напоминает в начале сессии.

**1. Лестница ponytail — перед КАЖДЫМ структурным решением, не после него.**
`YAGNI → reuse → stdlib → native → dep → one-liner`. Новая колонка, таблица, модуль, абстракция,
зависимость, правка схемы — прогнать и **назвать выигравшую ступень вслух**. Гоняется по
требованиям и диагнозу, а не только по коду.

**2. Consult-first — скил открывается В МОМЕНТ действия, а не один раз в начале сессии.**
Забываются те, чей триггер — момент, а не задача:

| Момент | Скил |
| --- | --- |
| Объявляешь работу сделанной | `verification-before-completion` |
| Коммит, мёрдж, PR, закрытие ветки | `finishing-a-development-branch`, `requesting-code-review` |
| Правишь событие аналитики или `docs/ANALYTICS.md` | `instrumenting-analytics` — реестр **перед** кодом |
| Что-то сломано, флапает, висит | `systematic-debugging` |
| Новое поведение или воспроизводимый баг | `test-driven-development` |
| Получил ревью или замечания | `receiving-code-review` |

Карта — `.claude/skills/INDEX.md`.

**3. Словарь — перед вводом нового термина.** Доменные — `CONTEXT.md`, сокращения и технические
понятия — `docs/GLOSSARY.md`. Новое добавляй строкой туда же. **Синонимы не плодить:** одно
понятие — одно слово во всех носителях.

**4. Модель предметной области — в одном файле.** Проект может завести отдельный файл под
числовую модель (тарифы, ставки, формулы) — встретил её число в любом другом месте, это
разошедшаяся копия, править на месте переписыванием, не врезкой.

**5. Поправка переписывает утверждение на месте.** Ни одного «~~было~~ стало», ни одной врезки
«ПОПРАВКА». Активный документ читается сверху вниз как действующая правда.
