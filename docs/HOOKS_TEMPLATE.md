# Hooks — реальный контур и шаблон для машинно-зависимых

Hooks исполняет харнесс Claude Code, НЕ модель — так реализуются правила вида «каждый раз при
X». В [`.claude/settings.json`](../.claude/settings.json) блока с примерами нет намеренно: это
JSON без комментариев, и любой закомментированный (переименованный в `_...`) пример события —
даже `_PreToolUse` — всё ещё распознаётся загрузчиком настроек как объявление хука по имени
события (проверка ищет эти имена как подстроку ключа, а не точное совпадение), из-за чего он
помечает файл как невалидный и **перестаёт применять permissions и остальные настройки из
всего файла**. Поэтому примеры машинно-зависимых хуков живут здесь, вне `settings.json`, а не
в самом файле настроек.

## Что стоит сейчас

Полный текст каждого правила и его «почему» — в комментарии-заголовке файла хука; здесь —
только карта событие → матчер → файл, чтобы не искать её по `.claude/hooks/*.js`.

| Событие | Матчер | Хук | Модуль | Зачем |
| --- | --- | --- | --- | --- |
| `PreToolUse` | `Bash\|PowerShell` | `protect-irreplaceable.js` | всегда | запрещает (exit 2) удаление и перезапись того, чего нет в git: `.env` и прочие секреты, тома Docker, `git clean -x`. Стоит первым — единственный носитель, ветки и worktree неотслеживаемые файлы не защищают |
| `PreToolUse` | `Bash\|PowerShell` | `contour-own-worktree.js` | контур хуков | запрещает любой сессии, включая супервизора, заводить ветку и переключаться с `main` в основном каталоге (судит каталог `cd`/`git -C`; `git switch main` и откат файлов можно) — правило «свой worktree» без хука держалось только самодисциплиной; экспортирует `onContour` для `session-start.mjs` |
| `PreToolUse` | `Bash` | `pre-commit-reminder.js` | контур хуков | на `git commit`/`git merge` напоминает про `verification-before-completion`, `finishing-a-development-branch`, ступень лестницы, словарь, строку `planning/INDEX.md` — не блокирует, гейт на `main` уже есть в `githooks/pre-commit` |
| `PreToolUse` | `Edit\|Write` + `if: Edit(docs/ANALYTICS.md)` | `analytics-registry.js` | контур хуков | реестр событий правится раньше кода, не после — напоминает открыть скил `instrumenting-analytics` |
| `SessionStart` | — | `session-start.mjs` (+`session-start.md`) | контур хуков | подмешивает в контекст правила, чей триггер — момент, а не задача: лестница ponytail, consult-first по моментам, словарь, модель предметной области в одном файле, поправка на месте. Кроме таблицы «момент → скил» все они стоят и в каноне — хук напоминает, а не подменяет носителя, поэтому опт-аут контура правил не отменяет. На страховочном контуре добавляет предупреждение о консервативной полосе (ADR-0002) — предикат контура общий с `contour-own-worktree.js` |
| `SubagentStart` | — | `session-start.mjs` (+`session-start.md`) | контур хуков | тот же текст — субагенту (`Agent`, исполнитель плана): субагент не сессия, SessionStart на нём не срабатывает. Имя события скрипт берёт из входа хука (`hook_event_name`). В тексте — и форма сдачи работы супервизору (девять пунктов `executing-plans`) |

Ключ `hooks` в `.claude/settings.json` несёт перечисленные строки — это не пример, а рабочий
контур, собранный из находок практики (разбор истории сессий в репозитории темплейта-родителя, см. `docs/METHODOLOGY.md`).
**Столбец «Модуль» читается вместе с таблицей модулей `docs/METHODOLOGY.md`:** строки модуля стоят в `settings.json`
только пока модуль включён, и таблица выше говорит, что модуль приносит, а не что непременно
стоит у вас. Выключены оба модуля — остаётся один `protect-irreplaceable`. `on-stop.ps1`
(озвучивание, `docs/SPEECH_SETUP.md`) регистрируется отдельно и опционально — он не входит в
этот список, потому что не включён в `settings.json` по умолчанию.

## Хуки — CommonJS, и `.claude/hooks/package.json` это закрепляет

Хуки написаны на `require`. Корневой `package.json` проекта с `"type": "module"` (так у любого
Vite-проекта по умолчанию) делает каждый `.js` под ним ES-модулем, и хук падает с
`ReferenceError: require is not defined` и exit 1. Для `PreToolUse` exit 1 — **не блокировка**:
команда проходит, и `protect-irreplaceable` молча пропускает `rm .env`. Поэтому в каталоге хуков
лежит `package.json` с `{"type": "commonjs"}` — ближайший `package.json` побеждает корневой.
Проверка после любой правки хуков: `node --test .claude/hooks/protect-irreplaceable.test.js`
и ручной прогон `rm .env` через хук — ожидается exit 2.

## Кириллица в выводе хука — форсировать UTF-8, не полагаться на дефолт

Хук или скрипт, печатающий кириллицу (`systemMessage`, `additionalContext`, текст в stdout),
обязан форсировать UTF-8 явно. Без этого сообщение приходит «кракозябрами» ровно в тот момент,
когда оно важно — искажение не видно на английском тексте и не ловится глазом при разработке.
Механизм называется для каждого языка контура, а не общий запрет:

- **Node** (весь текущий контур хуков) — `process.stdout.write()` пишет строки как UTF-8 по
  умолчанию, отдельного шага не требуется; это стоит знать, чтобы не чинить то, что не сломано.
- **PowerShell** — `$OutputEncoding` при передаче текста во внешний процесс по умолчанию
  US-ASCII, а `[Console]::InputEncoding` при чтении stdin на русской Windows — `cp866`. Фикс на
  обоих концах уже стоит в `.claude/hooks/on-stop.ps1`:
  `$OutputEncoding = [System.Text.Encoding]::UTF8` в начале скрипта на запись,
  `New-Object System.IO.StreamReader([Console]::OpenStandardInput(), [System.Text.Encoding]::UTF8)`
  на чтение, минуя `Console.InputEncoding`. Разбор — `docs/SPEECH_SETUP.md`.
- **Python** — интерпретатор выбирает кодировку stdout по локали процесса, которая на Windows не
  всегда UTF-8. Форсировать переменной окружения `PYTHONIOENCODING=utf-8` перед запуском или в
  самом скрипте — `sys.stdout.reconfigure(encoding='utf-8')` до первой печати.

## Машинно-зависимые хуки — пример, а не файл

Хук, завязанный на конкретную машину (путь, локально установленный инструмент, особенность
конкретного железа), в шаблон не переносится файлом — он не переживёт копирование на другую
машину и будет молчать (или упадёт) непредсказуемо. Место такому хуку — пример здесь, полное
решение пишет сессия, которая настраивает контур под свою машину.

**Пример: единственная точка запуска для инструмента с машинными граблями.** Донор этого
приёма — хук, запрещавший запускать Android-эмулятор иначе чем через фиксирующий скрипт: при
масштабе окна «авто» эмулятор на мониторах с разным DPI ставил окно на стык, а при завершении
работы сам возвращал «авто», так что грабли возвращались на следующий сеанс. Хук решал это не
однократной инструкцией в памяти (её забывают), а блоком самой команды:

```js
// PreToolUse на Bash/PowerShell: запрещает запуск <инструмента> иначе чем фиксирующим скриптом.
// Почему: у <инструмента> есть машинная особенность (см. описание), которую скрипт обходит,
// а прямой запуск — нет. Хук молчит, если скрипта на машине нет (машинно-зависим намеренно).
const fs = require('node:fs');
const SCRIPT = 'C:\\path\\to\\fixing-script.ps1';
const DIRECT_LAUNCH = /\bpath-to-raw-launch-command\b/;

function decide(command) {
  if (!DIRECT_LAUNCH.test(command)) return null;
  if (!fs.existsSync(SCRIPT)) return null; // скрипта на машине нет — не наш случай
  return `запускай через ${SCRIPT}, не напрямую — см. комментарий выше`;
}
module.exports = { decide };
// … stdin → decide → exit 2 с сообщением, как в protect-irreplaceable.js
```

Регистрировать такой хук в боевом `.claude/settings.json` только на той машине, где он
применим, и держать сам файл вне `git` (`.claude/settings.local.json`) либо за флагом в
проектном `settings.json`, который явно называет машину.

## Как добавить обычный (не машинно-зависимый) хук

1. Выбери событие (`SessionStart` / `PreToolUse` / `Stop` / другое — см. `/help` и документацию
   Claude Code по hooks; перечня событий этот файл не дублирует) и матчер.
2. Допиши запись в существующий массив под ключом `hooks` в `.claude/settings.json` — не
   создавай второй ключ того же события, дополняй массив матчеров. Если новый матчер трогает
   `PreToolUse`, `protect-irreplaceable.js` остаётся первым в своём матчере.
3. Проверь: `node -e "JSON.parse(require('fs').readFileSync('.claude/settings.json','utf8'))"`
   без ошибки, и в новой сессии `permissions` продолжают действовать (разрешённая команда не
   спрашивает подтверждения).

> **Проверять только там, где принято доверие.** Пока диалог доверия к репозиторию не принят
> ни разу, проектный `permissions` не применяется вовсе — при том, что ключ `hooks` из того же
> файла исполняется, и файл выглядит рабочим. В неинтерактивном режиме (`claude -p`, вывод в
> пайп) диалог не показывается, а невалидные файлы настроек игнорируются молча, без сообщения.
> Отсюда правило: свежеинициализированный проект **один раз открывают интерактивной сессией**
> и принимают доверие — до этого судить о `permissions` нельзя. Принимается оно на репозиторий:
> связанные `git worktree` наследуют принятие основного клона, своей записи им не нужно
> (проверено 2026-09-28: минимальный валидный `settings.json` без принятого доверия даёт то же
> отклонение, что и полный, а после принятия в основном клоне заработали оба).
