# Architecture Decision Records (ADR)

Необратимые / дорогие-к-откату решения — **по одному файлу на решение**. Дополняет `CONTEXT.md` и
`docs/GLOSSARY.md` (там — где живёт термин; здесь — где живёт решение) и раздел «Работа с кодом»
канона `AGENTS.md` (там — как писать код; здесь — почему решено так).

## Правила

- **Файл-на-решение:** `NNNN-slug.md`, номер — сквозной инкремент (`0001`, `0002`, …). Шаблон —
  [`0000-template.md`](0000-template.md).
- **Префикс `T` — решения шаблона-родителя:** `T0005`… — ADR шаблона под его же номером, привезённые
  при синхронизации; ссылки на них — `ADR-T00NN`. Свои решения проекта префикс не получают и
  нумеруются дальше своей линии. `0001`–`0004` общие с шаблоном — завелись до разделения линий.
  Ссылки внутри T-ADR и `0001`–`0004` на `planning/archive/…` и `INIT.md` ведут в репозиторий
  шаблона — это история, её не переписываем. Где шаблон — [`../METHODOLOGY.md`](../METHODOLOGY.md).
- **Только необратимое / удивительное / с реальным трейд-оффом.** Обратимое остаётся в плане/PR,
  а не здесь (см. скилы `domain-modeling`, `grill-with-docs`).
- **Историю не переписываем:** устаревшее решение не редактируем на месте — заводим новый ADR со
  `Status: Accepted`, а старому ставим `Superseded by ADR-XXXX`.
- **Кросс-линк:** из кода/комментария, который ADR ограничивает, ссылаться на конкретный
  `docs/adr/NNNN-*.md`; из `CONTEXT.md` — если ADR определяет термин.
