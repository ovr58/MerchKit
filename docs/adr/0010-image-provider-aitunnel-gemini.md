# ADR-0010: Провайдер изображений — AITunnel / `gemini-3.1-flash-image`, узнаваемость 6 из 7

- **Status:** Accepted
- **Date:** 2026-08-30
- **Related:** [ADR-0005](0005-ai-provider-abstraction.md) · `docs/SPEC.md` §2, §5 ·
  `docs/TZ.md` §10, §11 · план вехи M5, шаги 0 и 2
  (`planning/active/m5-real-provider_2026-08-29.md`) ·
  [`UNIT_ECONOMICS.md`](../../planning/reference/UNIT_ECONOMICS.md) §8

## Context

[ADR-0005](0005-ai-provider-abstraction.md) сознательно отложил выбор вендора до практической
проверки на реальных фото товаров — качество продукта упирается ровно в одну характеристику
провайдера: способность сохранить предмет с загруженного фото узнаваемым (`TZ.md` §10, главный
риск продукта).

**Шаг 0 вехи M5** снял вопрос «какие вендоры сравнивать» — решением пользователя 2026-08-29
названы конкретные модели одного и того же шлюза (AITunnel, единственный доступный из РФ
маршрут к Gemini): `gemini-3.1-flash-image` для изображений, `gemini-3.1-flash-lite` для
дешёвых текстовых операций. Шаг 2 из «выбора кандидата» стал **проверкой назначенного**.

**Шаг 1** зафиксировал критерий узнаваемости до прогона — четыре пункта (тот же предмет, форма,
цвет/надписи/логотипы, число объектов) и пороговое правило: кандидат проходит, если узнаваемы
**все** наборы контрольной выборки из семи реальных CC-лицензированных фото.

### Первый боевой прогон — 4 из 7

Бюджет 500 ₽, потрачено 309,92 ₽. Текстовая половина контракта (`recognize`, `moderate`,
`composeCard`, `nameGeneration` — все через `gemini-3.1-flash-lite`) прошла начисто: 7 из 7 по
категории, NFR-01 (максимум 1,9 с при бюджете 5 с), модерация без единого ложного отказа.

Изображения — 4 из 7 узнаваемы. Три устойчивых провала:

1. `accessories-sunglasses` — подмена предмета: на входе сложенные очки в тонкой пластиковой
   оправе, на выходе — типовые «авиаторы» на металлической оправе (вендор сам подписал
   «Модель: Авиатор»).
2. `home-chair` — сдвиг цвета: салатовая и бордовая полосы обивки заменены на канонические
   жёлтую и красную, модель прочла три цветных блока как флаг.
3. `food-pepsi` — потеря объекта: со входа исчезла отдельная банка рядом с упаковкой, остался
   только короб.

Отдельно подтверждена **недетерминированность**: тот же запрос на том же наборе
(`accessories-watch`) дал в одном вызове верную надпись «СДЕЛАНО В СССР», в другом —
искажённую «СЕКЗАНО & СССР». Единичный вердикт по любому набору — оценка снизу, не факт.

### Три провала разобраны порознь, 2026-08-30

**`food-pepsi` — пересмотр критерия, не техническая правка.** Решение пользователя: товар —
упаковка (12 банок), отдельная банка на референсном фото — постановочный приём фотографа, не
часть товара; печать банки на самой упаковке вендор сохранил без искажений. Критерий шага 1
уточнён: реквизит-постановку можно опускать, если сам товар передан точно. Засчитан пройденным.

**`home-chair` — техническая правка, проверена на трёх повторах.** Первая гипотеза («слово
„триколор“ в названии — триггер») проверялась переименованием без этого слова, но тест вышел
испорченным: новое название само явно назвало канонические цвета флага текстом. Настоящая
причина оказалась шире формулировки конкретного товара — модель вообще склонна читать
несколько цветных блоков как флаг. В `imagePrompt()` (`aitunnel.ts`) добавлена **постоянная**,
не привязанная к одному товару оговорка: цветные блоки — не флаг, не герб, не чужой логотип,
сохранить оттенки с фото. Три повтора подряд с этой оговоркой дали три разных, но ни разу не
канонически-флажных результата (один вызов даже сам написал в тексте карточки «дизайн, не
повторяющий канонические флаги»). Засчитан пройденным, оговорка осталась в коде навсегда.

**`accessories-sunglasses` — попытка починить не удалась.** Гипотеза: очки на фото сложены,
модель не может восстановить истинную форму по одному неоднозначному ракурсу и подставляет
знакомый архетип. Проверка: явный запрет («НЕ авиаторы с металлической оправой») в описании,
три повтора. Результат — **0 из 3**: дважды снова авиатор, один раз другой обобщённый силуэт
(кэт-ай). Вывод: причина не в формулировке промпта, а в нехватке информации на единственном
ракурсе — словом это не чинится. Второго ракурса этого конкретного предмета не существует (фото
с одного случайного CC-поста), проверить гипотезу «несколько ракурсов помогут» не на чем.
**Остаётся единственным непройденным набором.**

Обновлённый счёт: **6 из 7**. Пользователь подтвердил 2026-08-30, что этого достаточно —
седьмой набор не преследуется дальше, а остаётся задокументированным остаточным риском.

### Экономика — известное следствие, не решённое здесь

Фактическая себестоимость по логам шлюза (`usage.cost_rub`): изображение 11,54–11,69 ₽ на
бакете 1K, 17,25–17,59 ₽ на 2K; текстовые операции ≈ 0,19 ₽; генерация целиком —
**11,88–17,59 ₽** против утверждённых **4,13 ₽**
([`UNIT_ECONOMICS.md`](../../planning/reference/UNIT_ECONOMICS.md) §8, считалась по прайсу
Gemini 2.5 Flash Image). Валовая маржа пакета «Про» падает с 88,7% до 64,5–47,5%, «Стандарт» —
с 78,0% до 67,4%. В убыток не уходим ни на одном пакете, но расхождение реально и требует
отдельного решения — сверка себестоимости с ценой в баллах остаётся работой шага 4, не
поглощается этим ADR.

### Рассмотренные альтернативы

1. **Сравнить с другим вендором/моделью до решения.** Не пошли этим путём: пользователь на
   шаге 0 назвал конкретные модели напрямую, шаг 2 стал проверкой назначенного, а не открытым
   сравнением. Сравнение остаётся доступным запасным ходом, если бы 6 из 7 не устроило.
2. **Добиваться 7 из 7.** Не пошли: причина оставшегося провала понятна, для него уже есть
   путь исправления в продукте (несколько ракурсов при загрузке — FR-02 уже поддерживает до
   четырёх фото), а гнаться дальше на этом конкретном тестовом фото — тратить бюджет без
   гарантии результата на нерепрезентативном случае (продавцы обычно грузят больше одного фото).

## Decision

**Провайдер — шлюз AITunnel; модели — `gemini-3.1-flash-image` для изображений,
`gemini-3.1-flash-lite` для распознавания, модерации, текстов карточки и названия генерации.**
Реализация уже существует (`supabase/functions/_shared/ai-provider/aitunnel.ts`, шаг 3 плана
вехи M5) — этот ADR фиксирует найденное на шаге 2 основание для выбора, а не меняет код.

Критерий узнаваемости пройден на 6 из 7 набора контрольной выборки, с одним
задокументированным, понятым и принятым остаточным риском.

## Consequences

**Обязаны:**

- Держать постоянную анти-флаговую/анти-логотипную оговорку в `imagePrompt()` — она общая, не
  специфична для кресла, и защищает любой будущий товар с цветными блоками или полосами.
- Поправить `docs/SPEC.md` §2 — строка провайдера называла устаревшую `gemini-2-5-flash-image`
  (решение от 2026-08-27, до сверки с живым каталогом шлюза).
- Довести до конца шаг 4 плана вехи M5: миграция себестоимости рядом с `generationId` и
  отдельное решение пользователя по разрыву цены в баллах (4,13 ₽) с фактом (11,88–17,59 ₽).
- Не считать `accessories-sunglasses` починенным — при разборе похожих жалоб пользователей
  («не тот силуэт») в проде первым делом проверять, был ли загружен один неоднозначный ракурс.

**Чего нельзя:**

- Пропускать шаг 8 (боевые сценарии US-E2/US-E4) — 6 из 7 узнаваемости не заменяет проверку
  отказов и восстановления на этой же конфигурации.
- Тихо убирать анти-флаговую оговорку при рефакторинге `aitunnel.ts` — без неё воспроизводится
  находка `home-chair`, а причина в коде документирована только там же.

**Что теряем:** гарантию точного силуэта для товаров с неоднозначной формой на одном ракурсе
(сложенные, частично раскрытые предметы) — на уровне промпта это не лечится; единственная
известная мера — несколько ракурсов при загрузке, уже поддерживаемая продуктом (FR-02), но не
усиленная в UX мастера под этот конкретный риск.

**Что не меняется:** контракт `ai-provider` из пяти операций (ADR-0005, дополнен `moderate` на
шаге 0 вехи M5) — выбор вендора его не трогает, ровно как и задумано абстракцией.
