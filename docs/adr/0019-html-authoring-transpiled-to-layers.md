## Context

Прогон арт-директора (ADR-0018, шаг B5.10 плана сборки карточки) показал: правка боксов вслепую
не лечит главный брак — белый текст на светлом кадре, обрезанные надписи, текст на товаре.
Владелец оценил дизайн как «швах» при отличном вырезе. Причина в постановке, а не в модели:
арт-директор кадра не видит (ADR-0018 п. 1 запретил показывать картинку) и говорит на нашем
JSON-языке слоёв, которого ни одна модель не видела в обучении. Цвета, кегли и состав слоёв ему
менять нельзя, поэтому контраст он не может исправить по построению.

Гипотеза владельца: модель верстает карточку на своём родном языке — HTML и CSS — по кадру,
текстам продавца и референсам лидеров выдачи, а детерминированный транспилятор переводит этот
HTML в наш язык слоёв. Проба 2026-10-05 (Claude Sonnet 5.5 через шлюз AITunnel, те же кадры, что
у прогона арт-директора, выход — HTML, снятый Chromium в размер холста) дала восемь карточек;
вердикт владельца по каждой из восьми — «HTML лучше», общий — «гениально!». Замечание
владельца: карточки однообразны, потому что все восемь получили одни и те же четыре референса.

Проба не доказала три вещи: что свободный CSS модели переводится в слои без потери вида; цену в
проде; устойчивость на сотне кадров. Это решение закрывает первое архитектурно (закрытое
подмножество CSS и гейт round-trip), остальное снимают шаги плана.

Почему это ADR, а не строка плана: решение заводит **новую платную операцию провайдера**,
меняющую себестоимость и цену карточки; **новую операцию сервиса выреза в соседнем репозитории**
(`ovr58/cutout_runner`) с браузерным движком на коробке; и **сквозной инвариант** «слои —
единственная истина», который держат одновременно провайдер, коробка, воркер генерации и
будущий редактор. Откатить — согласованно менять два репозитория, коробку, учёт затрат и прайс.

## Decision

**Карточку сочиняет модель в HTML и CSS — по кадру, текстам продавца и референсам; закрытое
подмножество CSS детерминированно переводится в макет и содержимое нашего языка слоёв; слои
остаются тем, что хранится, собирается и редактируется. HTML живёт ровно один шаг — от ответа
модели до перевода — и нигде не сохраняется как истина.**

### 1. HTML — язык сочинения; слои — хранение, рендер и вход редактора

ADR-0012 и ADR-0013 не пересматриваются. Сборка по-прежнему SVG → PNG по макету (`composeSvg`),
шрифты — роли, словари закрытые, у генерации хранится снимок макета. HTML — только форма, в
которой модель сочиняет: она пишет его бегло, а наш язык слоёв видит впервые. Скриншот Chromium
карточкой не становится никогда: оплаченная карточка — всегда сборка по слоям, и её пересборка,
смена шрифта и редактор работают с макетом, как сегодня. Транспилированный макет для всех
потребителей — обычный макет; отдельного вида «HTML-макет» нет.

### 2. Где работает сочинение — в рантайме, на каждой платной карточке (Q-H1)

Сочинение идёт в воркере генерации на каждой платной генерации типа «карточка», после кадра
вендора и выреза, а не офлайн при наборе библиотеки. Библиотека макетов (ADR-0013) остаётся: из
неё берётся макет отката (п. 6) и макет превью до оплаты. Разбор образцов в библиотеку через HTML
этим решением не вводится — он остаётся записью на будущее.

Выключатель — секрет `CARD_AUTHOR=on`; любое другое значение или его отсутствие — путь
библиотеки, как сегодня. Код едет в стейдж выключенным и включается командой владельца после
платного пробного прогона, а не деплоем. На карточке с включённым сочинением арт-директор
(`directCard`) не зовётся.

### 3. Операция провайдера `authorCard` и модель сочинения (Q-H2)

- **Имя:** `authorCard` — новая операция `ai-provider`, рядом с `directCard`. В `ProviderUsage['operation']` и в
  проверку `generation_costs.operation` добавляется `'authorCard'`; каждый вызов пишется строкой
  затрат с ценой из ответа шлюза.
- **Вход:** кадр вендора (картинка — модель его видит), тексты продавца (заголовок, описание,
  свойства «подпись — значение», пожелания), площадка, категория, холст в пикселях профиля
  площадки, **не больше четырёх референсов** (п. 7); первый референс назван в задании ведущим —
  его композицию модель берёт за основу.
- **Выход:** одна HTML-страница по форме ответа скила-жанра (п. 8) — первый блок ```html``` в
  ответе; блока нет — отказ операции. Разбор ответа — наш, одинаковый для любого вендора и для
  заглушки; заглушка отдаёт записанную фикстуру.
- **Модель:** Claude Sonnet 5.5 через шлюз AITunnel, отдельная переменная окружения
  `AI_PROVIDER_AUTHOR_MODEL` (значение `claude-sonnet-5.5`) — не `AI_PROVIDER_TEXT_MODEL`
  арт-директора. Opus сочинением не зовётся, пока его не замерили отдельным прогоном по слову
  владельца; смена модели — значение переменной и строка здесь, а не правка кода.
- **Потолок ответа держится низким:** шлюз резервирует деньги на балансе по `max_tokens`, а не по
  факту, и завышенный потолок отбивает запрос при живом балансе.

### 4. Транспилятор: сцену снимает Chromium на коробке выреза, перевод — общий код

Транспилятор — два шага с разной природой:

- **Снятие сцены** — Chromium раскладывает HTML (переносы строк, обмер текста, каскад стилей) и
  отдаёт `HtmlScene`: боксы элементов в пикселях, вычисленные стили, строки текста. Это делает
  новая операция сервиса выреза **`POST /layout`** — в том же процессе Node на коробке, что
  `/cutout` и `/mask` (ADR-0015 п. 1: сервис один). Ответ — только JSON сцены, без скриншотов.
- **Перевод сцены в макет и содержимое** (`toLayout`) — чистая функция без ввода-вывода в общем
  коде `card-layout/`; её исполняет воркер, а офлайн-инструменты зовут ту же функцию.

**Не в изоляте Edge Function:** раскладка текста требует браузерного движка, а в изоляте нет ни
браузера, ни места под него — сборка уже упирается в его пределы (ADR-0015). **Не в браузере
продавца:** результат определяет оплаченную карточку и должен быть одинаков для всех — чужой
движок, чужие шрифты и снятая вкладка дают другую раскладку или никакой, а браузерный путь
ADR-0015 уже отверг.

**HTML от модели — недоверенный ввод.** Граница доверия коробки (ADR-0016) сохраняется целиком:
ключей проекта на коробке нет, право звать — тот же общий секрет, лимиты тела — на nginx. Сверх
того Chromium на `/layout` работает без сети (разрешён только кадр из тела запроса), без
исполнения скриптов, с потолком размера тела и таймаутом; HTML со скриптом или внешним ресурсом
отвергается до раскладки.

`/layout` не предрешает переезд сборки на коробку: сборка остаётся в изоляте, и за карточку
выходит два обращения к коробке (вырез и сцена). Переезд сборки — прежний открытый вопрос
ADR-0015, а не следствие этого решения.

### 5. Подмножество CSS закрыто и совпадает со словарём слоёв

Модель получает не свободный CSS, а **закрытое подмножество**, где у каждой строки ровно один
способ записи и ровно одно отображение в наш язык: холст `#card`, кадр — `img#frame`, плашка —
блок с фоном без текста (`shape`), надпись — абсолютно позиционированный элемент с текстом
(`text`), плашка с подписью — два слоя одним боксом; пиксели переводятся в доли холста, гарнитура
— в роль шрифта, порядок в документе — в `z`. Запрещено всё, чему в словаре слоёв нет пары:
трансформации, фильтры, `<svg>`, псевдоэлементы, внешние ресурсы, относительные единицы, сетки и
флексы на текстовых боксах. Таблица «CSS → слой» и список запретов — `SUBSET.md` (шаг B1), а не
этот ADR: подмножество растёт вместе со словарём.

Всё, что вне подмножества, — **отказ транспилятора до рендера**, а не догадка: тот же приём, что
закрытые словари ADR-0012 п. 3 — то, чего нет в словаре, становится отказом проверки до сборки,
а не браком в оплаченном кадре. Закрытое по-прежнему не значит замороженное: подмножество
расширяется, когда гейт round-trip (п. 6) находит нехватку, и тогда расширяется словарь слоёв
обычным порядком ADR-0012.

### 6. Приём ответа — целиком; отказ — макет библиотеки, бесплатно

Сочинённая карточка принимается **целиком или не принимается вовсе** — частичного приёма, как у
арт-директора, нет: HTML описывает композицию связно, и половина её — не карточка. Принимается,
если одновременно:

- сцена снята и в ней нет элементов вне подмножества (п. 5);
- `toLayout` не вернул ни одной проблемы: каждое свойство легло в словарь, `validateLayout`
  итогового макета пуст;
- `textMismatches` пуст: на карточке нет ни одного слова, которого нет во входных текстах
  продавца (решение 4 плана M7 действует и для HTML).

**Гейт round-trip** — скриншот Chromium против сборки по слоям, не больше порога шага B4 по доле
различающихся пикселей — проверяет **транспилятор**, а не каждую карточку: офлайн, на записанных
HTML пробы, до включения сочинения и после каждого расширения подмножества. В рантайме скриншот
не снимается (ответ `/layout` — только сцена), а значит, свойство «перевод не теряет вида»
держится тем, что подмножество, прошедшее гейт, закрыто.

**Любой отказ** — ответа нет, блока ```html``` нет, коробка недоступна, сцена с отказами,
проблемы перевода, чужие слова — откатывает генерацию на **сборку по макету библиотеки, как
сегодня**, без повторного вызова модели. Откат бесплатен сверх уже потраченного вызова, генерация
не падает, баллы не возвращаются — продавец получает карточку. Причина отказа пишется одной
строкой в журнал функции. Худший исход — сегодняшний.

**Снимок.** У генерации в `generation_cards.layout` хранится то, что реально собиралось
(ADR-0013 п. 5): при приёме — транспилированный макет с пометкой происхождения «сочинение», при
откате — макет библиотеки с пометкой «библиотека»; `layout_id` по-прежнему называет макет,
выбранный подбором. После сборки снимок не перезаписывается, пересборка читает его.

### 7. Референсы — каталог владельца, выбор без модели

Референсы — образцы карточек лидеров выдачи, которые владелец складывает в каталог
`card_references` (таблица + приватный бакет, чтение только service-role) с площадкой и
категорией. Для генерации берутся **не больше четырёх** чистой функцией без модели: сначала та же
площадка и категория, затем та же категория, затем любые; из кандидатов — детерминированной
ротацией по идентификатору генерации, чтобы соседние карточки получали разные наборы, а повтор
сборки — тот же; первый из выбранных — ведущий (п. 3). Это и есть петля улучшения: новый образец
в каталоге → следующая карточка опирается на него, без правки кода. Референс — не образец
библиотеки макетов: его не разбирают в слои, он только показывается модели.

### 8. Скил-жанр — константа кода провайдера

Скил-жанр — системный промпт с правилами жанра карточки маркетплейса (иерархия, контраст,
безопасная зона, только слова продавца, правило разнообразия по ведущему референсу) и строгой
формой ответа — живёт **константой в коде провайдера** и правится как код: изменением с ревью и
тестами. Не в базе и не в настройках: его форма ответа — это контракт с подмножеством
транспилятора (п. 5), и правка промпта без правки транспилятора ломает приём ответа на всех
карточках сразу. Рабочий черновик — `bench/html-probe/CARD_GENRE.md`; в код он переносится
текстом.

### 9. Что становится с ADR-0018

**Сочинение заменяет арт-директора как направление.** ADR-0018 получает статус «Superseded by
ADR-0019» в части:

- **п. 1** (операция `directCard`, постановка без кадра, патч `CardDirection`) — модель теперь
  видит кадр и сочиняет композицию целиком, включая цвета и кегли;
- **п. 2** (проверка патча по частям) — приём целиком (п. 6 здесь);
- **п. 5** (бесплатная предпроверка, когда звать) — сочинение зовётся на каждой платной карточке.

Ступенчатый отказ ADR-0018 п. 3 — свойство патча `directCard` и действует ровно там, где тот
зовётся. Контракт `POST /mask` (п. 4) остаётся в силе как операция сервиса выреза: этим решением
она не отменяется. Код `directCard` не удаляется: пока владелец не включил `CARD_AUTHOR` на
стейдже, путь арт-директора работает под своим выключателем `CARD_DIRECTOR`, как сегодня;
удаление кода арт-директора — отдельное решение после пробного прогона сочинения.

### Цена карточки в баллах (Q-H3)

Сочинение — платный вызов на каждой карточке, на порядок дороже арт-директора, которого оно
заменяет. Цена карточки с сочинением в баллах поднимается до варианта, **нейтрального к
утверждённой экономике**: надбавка к цене объекта покрывает вызов сочинения, вклад пакета и план
по объёму остаются прежними, утверждение §8 не пересматривается. Число, расчёт и места его копий
— `UNIT_ECONOMICS.md` §10, подраздел «Сочинение карточки в HTML», и его §11; в код прайса и в
копии оно вносится шагом C5 плана, а не этим ADR. Цена фотогенерации не меняется.

## Consequences

**Обязаны:**

- Держать слои единственной истиной: ни один потребитель — сборка, пересборка, смена шрифта,
  редактор, витрина — не читает HTML. HTML в базу не пишется.
- Держать подмножество CSS (`SUBSET.md`), форму ответа скила-жанра и `toLayout` согласованными в
  одном изменении: расхождение любых двух — отказ на каждой карточке.
- Прогонять гейт round-trip до включения `CARD_AUTHOR` и после каждого расширения подмножества;
  порог не подгоняется под результат.
- Проверять дословность (`textMismatches`) на каждой сочинённой карточке; без неё модель вернёт
  «ХИТ ПРОДАЖ».
- Писать затраты каждого вызова `authorCard`, в том числе отвергнутого: себестоимость без них
  занижена.
- Сделать в `ovr58/cutout_runner` операцию `POST /layout` с Chromium без сети и без скриптов;
  деплой и включение коробки — командой владельца.
- Внести цену карточки с сочинением в `UNIT_ECONOMICS.md` и её копии одним изменением (C5) и
  снять фактическую цену и долю откатов пробным прогоном (C6).

**Получаем:**

- Модель видит кадр и сочиняет на языке, которым владеет: контраст, место под текст и
  композиция решаются там, где их видно, а не вслепую по карте занятости.
- Предсказуемость сборки сохраняется: транспилированная карточка собирается тем же сборщиком,
  проверяется тем же валидатором и пересобирается бесплатно.
- Петля улучшения без кода: владелец добавляет образцы лидеров в каталог референсов — следующие
  карточки разнообразнее и ближе к лидерам.
- Регресса нет ни при каком ответе модели: отказ — сегодняшняя карточка по библиотеке.

**Ценой:**

- Платный вызов на каждой карточке — себестоимость карточки растёт кратно, отсюда новая цена в
  баллах (§10). Ожидание генерации — плюс время вызова сочинения (десятки секунд) и обращение к
  коробке.
- Chromium на коробке: память и время запуска браузера в одном процессе с инференсом выреза;
  второе обращение к коробке за карточку; ещё одна поверхность атаки, закрытая отключением сети
  и скриптов.
- **Превью до оплаты обещает содержание, а не композицию:** превью строится по макету
  библиотеки (кадра ещё нет, вызов платный), а оплаченная карточка при приёме сочинения выглядит
  иначе. Как сказать об этом продавцу на экране — вопрос владельцу при планировании C3.
- Выразительность ограничена словарём слоёв: то, чего в нём нет (тени текста сложной формы,
  трансформации), модель использовать не может, а приём, вышедший за подмножество, уходит в
  откат.
- Устойчивость на сотне кадров и доля откатов не измерены — поэтому выключатель и платный
  пробный прогон до включения.

## Alternatives

- **Оставить арт-директора на JSON-патче (ADR-0018).** Отвергнуто прогоном B5.10: правка боксов
  без кадра и без права менять цвета не лечит контраст, который и есть главный брак.
- **Показать арт-директору кадр и дать писать слои JSON напрямую.** Модель не видела наш язык
  слоёв ни разу и пишет его неуверенно; проба выбрала HTML как язык, на котором она беглая. Цена
  вызова с картинкой та же, выигрыш — только в языке.
- **Скриншот Chromium как итоговая карточка.** Отвергнуто: ломает ADR-0012 и ADR-0013 —
  пересборки, смены шрифта и редактора по слоям больше нет, а оплаченная карточка зависит от
  движка браузера на коробке.
- **Транспилировать без браузера (разбор HTML в изоляте).** Без движка раскладки нет переносов
  строк и обмера текста — именно того, что нужно, чтобы бокс и строки легли в макет.
- **Сочинять офлайн, в библиотеку (разбор образцов через HTML).** Модель не видит кадр
  конкретной генерации — брак «текст на товаре» возвращается. Владелец выбрал рантайм (Q-H1);
  офлайн-путь остаётся записью на будущее.
- **Opus 5.5 вместо Sonnet 5.5.** Не замерен (резерв шлюза выше баланса на дату пробы); Sonnet
  дал восемь из восьми «лучше». Возврат — только после отдельного замера по слову владельца
  (Q-H2).
