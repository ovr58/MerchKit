# ADR-0007: Vite + React-SPA без SSR; серверная логика только в Edge Functions

- **Status:** Accepted
- **Date:** 2026-08-27
- **Related:** [`SPEC.md`](../SPEC.md) §1, §2 · [`TZ.md`](../TZ.md) §3, §8 ·
  [ADR-0006](0006-supabase-as-backend.md)

## Context

ТЗ фиксирует «React.js», но не называет сборщик. Реальных вариантов два: Vite (одностраничное
приложение, статическая сборка) и Next.js (серверный рендеринг, серверные экшены).

Выбор выглядит как выбор инструмента, но им не является. Next.js приносит **собственный
серверный рантайм** — и рядом с Edge Functions из [ADR-0006](0006-supabase-as-backend.md)
появляется второе место, где физически может жить вызов AI-провайдера и изменение баланса.
Два таких места означают два набора секретов, два деплоя и — главное — двух кандидатов на роль
источника правды о балансе. Правило «баланс меняется только сервером и только вместе с записью
в `ledger`» перестаёт быть проверяемым взглядом на один каталог.

Откат дорог именно поэтому: переезд SPA → SSR после того, как написан биллинг, переносит не
вёрстку, а серверный код, деплой и схему конфигурации.

Аргументы в пользу Next.js в этом продукте не работают: приложение целиком за логином,
публичных индексируемых страниц нет, SEO-требований нет ([`TZ.md`](../TZ.md) §3).

## Decision

**Vite + React-SPA. Серверный рендеринг не используем. Вся серверная логика — исключительно
Supabase Edge Functions.**

- Сборка статическая (`npm run build`), деплой — на статический хостинг.
- В браузер уходят только `SUPABASE_URL` и `anon`-ключ. Ключ AI-провайдера и
  `SUPABASE_SERVICE_ROLE_KEY` — только в секретах Edge Functions.
- Понадобится публичная маркетинговая страница — она делается отдельной статической
  страницей, а не поводом переехать на SSR.

## Consequences

**Обязаны:**

- Держать всю привилегированную логику (вызов провайдера, любое движение баллов) в Edge
  Functions — других мест для неё в архитектуре нет по построению, и это проверяется взглядом
  на один каталог `supabase/functions/`.
- Восстанавливать состояние генерации запросом к БД, а не получать его отрендеренным с
  сервера. Это и так требует NFR-02 (статус переживает F5).

**Нельзя:**

- Заводить серверные роуты во фронтенде.
- Обращаться к провайдеру или менять баланс где-либо, кроме Edge Functions.

**Принимаем:** первая загрузка — пустой HTML плюс JS-бандл. За логином это приемлемо: пустой
экран видит только уже вошедший пользователь, а не поисковый робот и не случайный посетитель.

**Пересмотр — только новым ADR.** Поводом станет появление требования к SEO или к серверному
рендерингу каталога, а не желание попробовать другой фреймворк.
