# ADR-T0007: Путь работы с дизайном и уровень вовлечения выбираются на инициализации, дефолт — минимум

- **Status:** Accepted
- **Date:** 2026-09-05
- **Related:** ADR-0003 (spec-first интейк) · ADR-T0008 (граница с `VISUALS.md`) ·
  ADR-T0009 (направление синка) · `planning/reference/DESIGN_SYSTEM_RESEARCH.md` §1, §2, §10 ·
  `planning/archive/plans/design-system-workflow_2026-09-05.md`

## Context

Проект, поднятый из шаблона, доходит до вёрстки, ни разу не зафиксировав, откуда берутся
цвета, отступы, иконки и размеры. Модель додумывает их **каждый раз заново** — и додумывает
по-разному, поэтому экраны одного продукта расходятся между собой тем сильнее, чем их больше.
Это не вопрос вкуса: расхождение обнаруживается на этапе, где оно дороже всего — когда
свёрстано уже много.

Обратная крайность так же дорога. Дизайн-система, заведённая для утилиты командной строки на
200 строк, — то же золочение, что спецификация на 20 страниц для неё же. Лестница ponytail
отсекает такое по умолчанию, но только если у шаблона **есть чем ответить «нам этого не
надо»**: если единственный описанный путь — полный, отказ выглядит как недоделка, и его
дооформляют.

Третья сила — **момент выбора**. Дизайн-система, взятая после того как код написан,
оплачивается редизайном; взятая до требований — замораживает интейк («сначала определимся с
цветами»). Разведка (§1, §9 грабля 2) даёт ровно одну точку входа: **после ТЗ, до вёрстки**.
А это значит — на инициализации, потому что позже интейк уже закончен.

Четвёртая сила — **два разных исходных положения**, которые нельзя свести к одному сценарию:
дизайнер есть и отдаёт файл (путь **A**), либо дизайнера нет и систему приходится собирать из
готового кита (путь **B**). Инструкция, написанная только под A, для одиночного разработчика
бесполезна; написанная только под B — оскорбительна для команды с дизайнером.

Варианты, которые рассматривались:

1. **Дизайн-система всегда, одинаковая для всех проектов.** Отвергнут: нарушает правило меры
   и делает шаблон непригодным для `cli`/`backend-api`/`data-ml`, где UI просто нет.
2. **Дизайн-система по требованию — спросить «нужна ли».** Отвергнут по тому же основанию,
   по которому в ADR-T0005 отвергнут вопрос «нужна ли аналитика»: ответ на такой вопрос всегда
   «потом», и «потом» не наступает. Спрашивать надо **уровень**, предъявив дефолт.
3. **Уровень и путь выбираются на инициализации, дефолт предлагается по стековому профилю.**
   Принят.

**Почему дорого откатить:** уровень определяет, существует ли в проекте машинный источник
значений оформления. Поднять уровень позже — значит пройти по всей уже написанной вёрстке и
заменить литералы на токены; ссылки на `DESIGN_SYSTEM.md` к этому моменту разойдутся по
спецификации, генеральному плану и критериям приёмки. Это аудит всего UI, а не правка файла.

## Decision

**Путь (A / B / минимум) и уровень вовлечения (0–3) выбираются на инициализации, в блоке D
опросника, и записываются в [`docs/DESIGN_SYSTEM.md`](../DESIGN_SYSTEM.md).**

- **Лестница уровней:** **0** — дизайн-системы нет, решения по ходу · **1** — токены (цвет,
  типографика, spacing, радиусы) · **2** — токены + ассеты (иконки, растр, пайплайн экспорта) ·
  **3** — уровни 1–2 плюс заявленное соответствие библиотеки компонентов коду.
- **Дефолт предъявляется, а не выспрашивается.** Агент называет уровень по стековому профилю
  (таблица — `INIT.md` шаг 4) и просит подтвердить или изменить. Открытый вопрос «нужна ли
  дизайн-система» задавать запрещено.
- **Дефолты по профилям:** `web-react` — 1 (2 при иконочном наборе) · `react-native` — 1 ·
  `ios-xcode` — 1 · `desktop` — 1 · `backend-api`, `cli`, `data-ml` — **0**.
- **Уровень 0 — полноценный ответ, а не отказ.** Он записывается в `DESIGN_SYSTEM.md` вместе с
  обоснованием и закрывает блок D. Артефакт, заполненный по уровню 0, не содержит ни одного
  `TODO(пользователь):` и не требует аккаунта в Figma.
- **Уровень 3 записывается как «2 + соглашение».** Машинное соответствие «компонент дизайна ↔
  компонент кода» даёт только Code Connect, а он доступен с тарифа Organization (сверено
  2026-09-05). Ниже этого тарифа уровень 3 держится дисциплиной людей, и в реестре он
  фиксируется именно так — с явным указанием, кто эту дисциплину исполняет.
- **Путь B — стартовая позиция, а не приговор.** Проект без дизайнера берёт готовый **парный**
  кит (Figma-библиотека + кодовая библиотека одной системы, с переменными в ките), достраивает
  недостающее генерацией и дальше работает по процедуре пути A.
- **Тарифные пути равноправны.** Бесплатный (REST API + плагины-экспортёры) и платный
  (Professional, официальный MCP) описываются как два рабочих способа; ни один не объявляется
  единственно верным. Официальный Figma MCP на тарифе Starter в качестве пайплайна **не
  предлагается**: 20 вызовов в месяц (сверено 2026-09-05) — это проба, а не работа.

## Consequences

**Что теперь обязаны:**

- Провести блок **D** опросника до блока V: от выбора пути зависит, кто и чем рисует экраны.
- Завести `docs/DESIGN_SYSTEM.md` на **любом** уровне, включая 0: пустой реестр с записанным
  «уровень 0, потому что …» — валидный результат, отсутствующий файл — нет.
- Называть цену или лимит только вместе с **датой сверки**. Цифра без даты через полгода
  становится ложью, а на неё уже принято решение.
- Проверять парность кита до того, как строить на нём путь B: кит без переменных обнуляет
  пайплайн токенов целиком.

**Чего теперь нельзя:**

- Спрашивать «нужна ли дизайн-система» вместо предъявления дефолта по профилю.
- Трактовать уровень 0 как недозаполненный интейк и дооформлять его до единицы.
- Обещать на тарифе Starter пайплайн на официальном MCP.
- Обещать синхронность компонентов на уровне 3 ниже тарифа Organization.

**Цена:** блок D удлиняет интейк даже там, где ответ — «уровень 0». Принято сознательно: на
уровне 0 блок закрывается двумя вопросами, а неспрошенный выбор всплывает на вёрстке, где он
стоит переделки экранов.

**Границы решения:** ADR фиксирует **момент и форму выбора**, а не инструмент. Какой именно
редактор дизайна, кит и конвертер токенов взял проект — решение проекта, оно живёт в
`docs/DESIGN_SYSTEM.md` и меняется без правки этого ADR.
