# ADR-T0010: Переносимая методика поставляется модулями: включение — стековым профилем, выключение — по подтверждению владельца

- **Status:** Accepted
- **Date:** 2026-09-27
- **Related:** ADR-T0005 (дефолт предъявляется, а не выспрашивается) · ADR-T0007 (прецедент
  «уровень 0 — законный ответ») · ADR-0001 (`.claude/` — host-neutral склад методики) ·
  `INIT.md` шаги 4, 4б, 7 · [`docs/adr/README.md`](README.md) — правило «историю не
  переписываем»

## Context

Шаблон получает методики из проекта-донора **пачкой**: скилы, команды, разделы канона, хуки,
факты seed-памяти. Методика, навязанная проекту, которому она не нужна, выключается целиком —
вместе с полезной частью. Это уже проверено на дизайн-системе (ADR-T0007): пока у шаблона не было
чем ответить «нам этого не надо», отказ выглядел недоделкой, и его дооформляли до полного пути.

Вторая сила — **носители разной природы**. «Убрать методику» для каждого типа значит разное:
у хука выключатель — запись в `.claude/settings.json`, а файл остаётся лежать; у скила
выключатель — удаление каталога, потому что автообнаружение подтянет его иначе само; у ADR
выключателя нет вовсе, потому что историю решений не переписывают. Инструкция «удалите
ненужное» без этого различения даёт либо мёртвый хук, зарегистрированный в настройках, либо
удалённый ADR, то есть потерянную причину.

Третья сила — **состав**. Без одного места, где записано, какие файлы образуют один модуль,
это знает только тот, кто модуль привозил. Через полгода холодная сессия видит пять скилов, три
ADR и шесть хуков и не может сказать, где границы модуля; выключить его она не может, а значит
не выключит и пользователь.

Четвёртая сила — **цена удаления**. Удаляется не код, а *причина*, по которой правило
существует: скил и ADR несут опыт, купленный чужой ошибкой. Проект, удаливший их, теряет не
файл — он теряет знание и покупает те же грабли заново, своими деньгами. Поэтому удаление не
может быть шагом, который модель делает по своей оценке полезности.

Варианты, которые рассматривались:

1. **Манифест модулей плюс скрипт зачистки.** Отвергнут по лестнице ponytail: новый формат
   описания и новый код, который сам надо тестировать и поддерживать, ради операции, которая
   выполняется один раз за жизнь проекта.
2. **Каждый модуль сам объясняет, как его снять; единого списка нет.** Отвергнут: пять описаний
   в пяти файлах не дают сводной картины, а вопрос владельца звучит как «что вообще внедрено».
3. **Переиспользовать существующий паттерн шага 4 `INIT.md`** — предъявить дефолт по стековому
   профилю, удалять только по явному подтверждению. **Принят.** Выигравшая ступень лестницы —
   **reuse**: ни нового формата, ни кода, ни третьего механизма рядом с двумя работающими
   («Аналитика по умолчанию», «Дизайн-система по умолчанию»).

**Почему дорого откатить:** контракт наследуется каждым проектом, поднятым из шаблона, и
уезжает в его `INIT.md`, канон и критерии приёмки. Сменить форму переключателя позже — значит
пройти по всем проектам-потомкам и по всем модулям, которые к тому моменту приедут.

## Decision

**Единица включения и выключения переносимой методики — модуль, а не файл.** Модуль — это
названная методика, у которой есть одна строка в таблице шага 4б `INIT.md`: список носителей,
дефолт по стековому профилю и точный способ снять.

- **Состав и дефолты живут в одном месте — таблица «методический профиль», `INIT.md` шаг 4б.**
  Строка = модуль, столбец «Выключить» несёт точные пути. Второй копии состава нет нигде: ни в
  `README.md`, ни в этом ADR, ни в самих носителях. Две копии списка расходятся, и тогда
  выключение оставляет хвост.
- **Дефолт предъявляется, а не выспрашивается.** То же правило, по которому устроены «Аналитика
  по умолчанию» и «Дизайн-система по умолчанию» (ADR-T0005, ADR-T0007): называется дефолт по
  профилю и просится подтвердить или изменить. Открытый вопрос «нужна ли методика X» задавать
  запрещено — ответ на него всегда «потом».
- **Решает владелец.** Модель предъявляет дефолт, показывает список путей и исполняет ответ.
  Ни один модуль не снимается по инициативе модели, даже если она видит, что модуль ни разу не
  сработал: «не использовался» — не доказательство ненужности, а свойство выборки.
- **Выключение ≠ удаление.** У носителя с точкой регистрации выключатель — сама регистрация:
  хук снимается записью из ключа `hooks` в `.claude/settings.json`, файл хука остаётся лежать —
  вернуть его стоит одну строку. Удаляются только носители без точки регистрации: каталог
  скила, файл команды, факт seed-памяти со своей строкой в `memory-seed/MEMORY.md`, раздел
  канона.
- **Блок «Выключить» в шапке головного носителя — обратная ссылка, а не второй список.** Он
  содержит имя модуля, указание «выключается по `INIT.md` шаг 4б» и то, чего в таблице нет:
  **что перестанет работать**, если модуль снять. Путей в блоке нет.
- **ADR модуля живёт по правилу истории, а не по правилу модуля.** Различаются два момента:
  - **на инициализации** проект ещё не принимал этого решения — ADR модуля есть артефакт
    шаблона и удаляется вместе с остальными носителями, по тому же одному подтверждению;
  - **после инициализации** решение уже в истории проекта: ADR **не удаляется**, а получает
    `Superseded by` нового ADR «модуль снят, причина» — правило «историю не переписываем»
    ([`docs/adr/README.md`](README.md)). Носители снимаются тем же изменением.
- **Удаление — по явному подтверждению, одно на модуль, и одним изменением.** Подтверждение
  спрашивается за модуль целиком, а не за каждый файл: половина снятого модуля хуже целого —
  остаются висячие ссылки, и следующая сессия чинит их вместо работы.
- **Ссылки на снятый модуль снимаются тем же изменением.** Проверка — `grep -rn` по имени
  модуля и по каждому пути из его строки, как минимум по `AGENTS.md`, `INIT.md`, `README.md`,
  `.claude/skills/INDEX.md`, `.claude/settings.json`, `memory-seed/MEMORY.md`.
- **Стековая ось и хостовая ось — разные.** Шаг 4б выключает модуль по стеку; шаг 7 — по хосту.
  Носитель, работающий только в Claude Code (хуки, seed-память, автообнаружение скилов), в
  другом хосте мёртвый груз, но безвредный: он снимается вместе с адаптером хоста, а не строкой
  таблицы 4б.
- **Таблица переживает бутстрап.** Шаг 8 предлагает удалить `INIT.md` как бутстрап-артефакт;
  шаг 4б — исключение: пока модуль можно выключить, список нужен. Проект, удаляющий `INIT.md`
  целиком, сознательно отказывается от механизма опт-аута.

## Consequences

**Холодная сессия, которой сказали «модуль X не нужен», делает ровно это — и больше ничего:**

1. открыть таблицу шага 4б `INIT.md`, найти строку `X`, прочитать столбец «Выключить»;
2. показать владельцу список путей и спросить подтверждение — **одним вопросом на модуль**;
3. получив «да»: снять названные записи из `.claude/settings.json` (файлы хуков **оставить**),
   удалить остальные названные пути, удалить их строки в `memory-seed/MEMORY.md` и
   `.claude/skills/INDEX.md`, снять названные разделы канона;
4. с ADR модуля поступить по правилу выше: на инициализации — удалить; позже — `Superseded by`
   новым ADR с причиной;
5. удалить строку модуля из таблицы 4б;
6. прогнать `grep -rn` по имени модуля и по путям, убрать висячие ссылки — **в том же
   изменении**;
7. не получив «да» — не удалять ничего и записать, что модуль оставлен по решению владельца.

**Что теперь обязаны:**

- Заводить новый переносимый модуль **вместе со строкой в таблице 4б** — в том же изменении.
  Модуль без строки невыключаем, а значит будет выключен целиком и руками.
- Называть в столбце «Выключить» точные пути, а не «удалить лишнее»: столбец и есть список
  состава модуля.
- Ставить блок «Выключить» в шапку головного носителя модуля — обратной ссылкой на шаг 4б.
- Предъявлять дефолт по профилю на шаге 4б каждой инициализации, включая те, где ответ
  предсказуем.

**Чего теперь нельзя:**

- Спрашивать «нужна ли методика X» вместо предъявления дефолта.
- Снимать модуль или его часть по инициативе модели, без подтверждения владельца.
- Удалять файл хука вместо снятия его записи в `.claude/settings.json`.
- Удалять ADR модуля после инициализации — он supersede-ится, а не исчезает.
- Копировать таблицу 4б куда-либо ещё, включая `README.md` и этот ADR.
- Считать «модуль ни разу не сработал» основанием его снять.

**Цена:** шаг 4б удлиняет инициализацию на один экран даже там, где владелец принимает все
дефолты. Принято сознательно: ненаступивший выбор всплывает позже — в виде методики, выключенной
целиком вместе с полезной частью.

**Границы решения:** ADR фиксирует **форму переключателя и процедуру снятия**, а не состав
модулей и не их дефолты. Какие модули есть у проекта и что в них входит — таблица шага 4б;
она меняется без правки этого ADR.
