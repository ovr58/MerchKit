# Озвучивание в VS Code (TTS) — что приезжает из коробки и что доустановить руками

## Почему не через VS Code Speech напрямую

[VS Code Speech](https://marketplace.visualstudio.com/items?itemName=ms-vscode.vscode-speech)
даёт реалистичный голос (Azure Speech SDK) для чтения ответов вслух — но только внутри
**встроенной** чат-панели VS Code (значок-динамик у каждого ответа, команда
`workbench.action.chat.readChatResponseAloud`, настройка `accessibility.voice.autoSynthesize`).
Панель Claude Code — не native VS Code chat participant, поэтому ни значок, ни эта команда там не
появляются (проверено эмпирически: 2026-09-02, ни значка, ни реакции на команду). Из коробки VS
Code расширения сам не ставит — только предложит кнопкой при открытии workspace через
`.vscode/extensions.json`; но даже установленный, для Claude Code он не даёт того самого
реалистичного голоса.

Поэтому обе фичи ниже реализованы через `System.Speech` (штатный Windows TTS) — работает с любой
панелью, потому что вход — системный буфер обмена и Stop-хук харнесса, а не UI VS Code. Голос по
умолчанию (голоса "Desktop": Zira/David/Irina) заметно роботизированный.

## Скорость речи

Захардкожена в обоих скриптах (`.claude/hooks/on-stop.ps1`, `.vscode/speak-clipboard.ps1`) —
строка `$synth.Rate = 5`. Диапазон `System.Speech`: от `-10` (медленнее) до `10` (быстрее), `0` —
обычная скорость. Поменять — отредактировать это число в обоих файлах (значение не связано с
выбором голоса/языка, синхронизировать вручную). Влияет только на фолбэк `System.Speech` — у
Piper (ниже) своей регулировки скорости в этих скриптах нет.

## Выбор голоса и языка

Оба скрипта (`on-stop.ps1`, `.vscode/speak-clipboard.ps1`) сами определяют язык текста (кириллица
vs латиница по соотношению символов) и выбирают голос нужной культуры (`ru-RU`/`en-US`) — так
английский текст читается английским голосом, а не русским с акцентом. Внутри выбранного языка
предпочтение — голосу с именем, содержащим `Natural`, если такой установлен. Ручного переключения
не требуется.

## Windows "Natural" — тупик на этой машине

Раньше это был единственный план получить голос лучше System.Speech Desktop: Параметры →
Время и язык → Речь → Управление голосами → Добавить голоса → искать пометку «Natural». Проверено
2026-09-02 (Windows 11, build 26200) — таких голосов не предложено **ни для одного языка вообще**,
не только для русского. Даже если бы появился, `System.Speech` его не увидел бы — Natural-голоса
живут в отдельном реестровом дереве (`Speech_OneCore`, не `Speech`), которое читает другой API
(`Windows.Media.SpeechSynthesis`, WinRT); тот, в свою очередь, у обычного непакетированного
PowerShell-скрипта на этой машине возвращал 0 голосов даже при наличии записей в реестре. Ветка
закрыта — реальное решение ниже.

## Голос понатуральнее — Piper (опционально, локально, офлайн)

[Piper](https://github.com/rhasspy/piper) — нейросетевой TTS-движок, работает офлайн, отдельный
exe, Python не нужен. Звучит заметно естественнее `System.Speech`. Проект архивирован
(разработка ушла в [OHF-Voice/piper1-gpl](https://github.com/OHF-Voice/piper1-gpl), но там уже
только pip-пакет, без готового exe) — используется последний релиз до архивации, `2023.11.14-2`;
для офлайн-синтеза статичных голосовых моделей этого достаточно, обновлений не требуется.

**Установка (опционально, один раз на машине):**
```
powershell -File tools/piper/install-piper.ps1
```
Скачивает `piper.exe` (~21 МБ) + голоса RU/EN (~60 МБ каждый, суммарно ~140 МБ) в
`tools/piper/{bin,voices}/` — не коммитится (см. `.gitignore`), нужен интернет. Идемпотентно:
повторный запуск не перекачивает уже имеющееся.

**Голоса захардкожены** в `on-stop.ps1`, `.vscode/speak-clipboard.ps1` и `install-piper.ps1`
(имя должно совпадать во всех трёх):
- `ru_RU-irina-medium` (по умолчанию). Альтернативы — тоже голоса Piper, качество только
  "medium" (~60 МБ): `ru_RU-denis-medium`, `ru_RU-dmitri-medium`, `ru_RU-ruslan-medium`.
- `en_US-lessac-medium` (по умолчанию). У en_US голосов намного больше и есть уровни
  low/medium/high — полный список и сэмплы: https://rhasspy.github.io/piper-samples/.

Чтобы сменить голос — поменять `Name`/`Path` в массиве `$voices` в `install-piper.ps1` (комментарий
там же указывает, где брать имя пути на Hugging Face) и `$piperModelName` в обоих скриптах
озвучивания, затем перезапустить установку для новых файлов.

Скрипты озвучивания сами предпочитают Piper, если `tools/piper/bin/piper.exe` и нужная модель
на месте, и молча откатываются на `System.Speech`, если нет (или если сам синтез не удался) —
Piper не обязателен для работы фичи, только для качества голоса.

**Грабли с кодировкой (уже исправлено, но если будешь трогать эти скрипты — знай):**
Windows PowerShell по умолчанию кодирует текст, который пайпится во внешний exe, в **US-ASCII**
(`$OutputEncoding`), а не в UTF-8 — кириллица долетает до Piper как мусор, и Piper тихо (без
ошибки) синтезирует пустой звук (`audio=0 sec` в его логе). Фикс — `$OutputEncoding =
[System.Text.Encoding]::UTF8` в начале скрипта, уже стоит в обоих. Показывается только на
достаточно длинном/содержательном тексте — короткие тестовые фразы могли проходить и без фикса,
поэтому баг не был виден в первых тестах.

## 1. Озвучить выделенный текст вручную (кнопка/сочетание)

Что приезжает из коробки: `.vscode/tasks.json` → задача `Speak Clipboard` (читает буфер обмена,
говорит его через Piper, если установлен, иначе через `System.Speech`). Что нужно один раз руками
**на каждой машине** (VS Code не
поддерживает `.vscode/keybindings.json` — сочетания клавиш всегда пользовательские, шаблоном не
разносятся):

1. Выделить текст → `Ctrl+C` (обычное копирование, работает в любой панели, включая чат).
2. Либо `Ctrl+Shift+P` → `Tasks: Run Task` → `Speak Clipboard`, либо один раз добавить в
   пользовательский `keybindings.json` (`Ctrl+Shift+P` → `Preferences: Open Keyboard Shortcuts (JSON)`):
   ```json
   {
     "key": "ctrl+alt+r",
     "command": "workbench.action.tasks.runTask",
     "args": "Speak Clipboard"
   }
   ```
   После этого — `Ctrl+C`, затем `Ctrl+Alt+R`.

Кликабельная кнопка в статус-баре средствами самого VS Code недостижима без ещё одного
маркетплейс-расширения (например, task-button-подобного) — сознательно не тянем лишнюю
зависимость; при желании пользователь добавляет её сам.

**Остановить озвучивание посреди фразы:** `System.Speech.Speak()` синхронный — прервать его можно
только убив процесс, который его вызвал. Задача `Stop Speaking` (`.vscode/stop-speaking.ps1`)
делает это сама: ищет процессы `powershell.exe`, запущенные с `on-stop.ps1` или
`speak-clipboard.ps1`, и завершает их. Сочетание — так же вручную, один раз на машине:
   ```json
   {
     "key": "ctrl+alt+s",
     "command": "workbench.action.tasks.runTask",
     "args": "Stop Speaking"
   }
   ```
Останавливает и ручное чтение буфера, и автоозвучивание по Stop-хуку — оба процесса матчатся
одним и тем же скриптом.

## 2. Автоозвучивание ответа по завершении хода

Что приезжает из коробки: `.claude/hooks/on-stop.ps1` (озвучивает `last_assistant_message` через
Piper, если установлен, иначе через `System.Speech`, если существует флаг `.claude/tts-enabled`)
и слэш-команда `/speech on|off|status`, управляющая этим флагом.

Чего в коробке **нет и быть не может** — регистрации самого Stop-хука: она машинно-зависима
(Windows-путь к `powershell.exe`, конкретная машина) и живёт в `.claude/settings.local.json`,
который в `.gitignore` и не коммитится. Сделать один раз на машине:

1. Скопировать блок `_hooks` (Stop) из `.claude/settings.local.json.example` в
   `.claude/settings.local.json`, переименовав `_hooks` → `hooks` (слить с уже существующими
   ключами, не перезаписывать файл).
2. `/speech on` — создаёт `.claude/tts-enabled`. `/speech off` — выключает. `/speech status` —
   проверяет текущее состояние и что хук вообще зарегистрирован.

Хук асинхронный (`"async": true`) — не блокирует сессию на время озвучивания — и с укороченным
таймаутом (30 с, лимит Stop-хуков), так что очень длинные ответы обрезаются до ~2000 символов
внутри `on-stop.ps1`.

## Перенос на другую ОС

И `System.Speech`, и скачанный Windows-бинарник Piper — Windows-only. На macOS/Linux `on-stop.ps1`
и `speak-clipboard.ps1` потребуют замены на `say`/`spd-say` (Piper при желании ставится и там
через `pip install piper-tts` из его преемника — см. секцию про Piper выше — но это уже другой
способ установки, не через `install-piper.ps1`).
