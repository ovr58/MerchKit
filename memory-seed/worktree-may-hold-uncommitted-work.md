Перед `git worktree remove` **обязательно** прогнать `git -C <дерево> status --porcelain`.
Пустая ветка в `git branch -vv` не означает, что сессия ничего не сделала: она могла выполнить
все шаги и закрыть сессию, не закоммитив, — в дереве при этом лежат готовые файлы.

**Why:** ветка и рабочее дерево — разные носители состояния. `git branch` показывает только
первый, а `worktree remove` уничтожает второй вместе с несохранённым. Отчёт «ветка пуста, шаги
не исполнялись» на одном `git log` — неверный вывод, который может стоить готовой работы.

**How to apply:** сводя ветки, сначала `git status` по каждому дереву, потом решения. Нашёл
несохранённое — коммитить за ту сессию, назвав в сообщении, что коммит собран из её дерева без
правок содержимого, и отдельно перечислив, что было проверено вручную.
