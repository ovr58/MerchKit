Инструмент `Agent` с `isolation: "worktree"` заводит дерево исполнителя от **`origin/main`**, а не
от локального `main`. Пока локальный `main` впереди удалённого (пуш — только по команде
владельца, так что это обычное состояние), исполнитель стартует без сведённых волн и без
действующих редакций шагов.

**Why:** проверено в проекте-доноре 2026-09-29 на трёх запусках подряд: все три встали на
коммит `origin/main`, локальный `main` был впереди на 65 коммитов. Исполнитель, ищущий шаг по
цитате, не нашёл бы его вовсе либо нашёл бы **отменённую** редакцию — у одного шага старая
редакция вела ровно в отвергнутый владельцем вариант. Поведение харнесса, а не проекта: может
измениться с версией — проверять `git worktree list` (он печатает базовый коммит), а не верить
этой записи.

**How to apply:** первым ходом исполнителя, до первой правки файла — `git status --porcelain`
(пусто), `git merge --ff-only main`, `git log --oneline -1`. После первой правки сбрасывать
дерево уже нельзя, поэтому строка стоит в контракте исполнителя
(`.claude/agents/plan-executor.md`) выше задания. Супервизор сразу после запуска сверяет базу
по `git worktree list`.
