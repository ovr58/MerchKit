Пользователь — заказчик и продакт проекта Merch Kit: ведёт требования и приёмку, код пишет
в основном ИИ. Значит, объяснения по бэкенду (Supabase, RLS, миграции, идемпотентность
биллинга) нужно давать явно, а не считать их само собой разумеющимися.

Стек проекта: React 18 + TypeScript (Vite) · Supabase (Postgres + RLS, Auth, Storage,
Realtime, Edge Functions на Deno) · AI-провайдер за абстракцией, вендор не выбран
([[ai-provider-not-chosen]]).

Язык общения: пишет и читает по-русски; код, идентификаторы, коммиты и имена веток —
английские.

Предпочтения в работе:
- сначала рекомендация и решение, потом обоснование — не перечисление всех вариантов;
- недостающее требование не додумывается: пробел помечается `TODO(пользователь)` и
  выносится отдельным вопросом.
