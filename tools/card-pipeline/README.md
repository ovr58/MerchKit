# Офлайн-конвейер образцов карточек

Административная часть вехи M7 (план
[`card-assembly-pipeline_2026-08-31.md`](../../planning/active/card-assembly-pipeline_2026-08-31.md)).
Пользователь сюда не заходит: здесь образцы разбираются на макеты, а базы иконок и шрифтов
пополняются. Пользовательский конвейер — фаза B — живёт в Edge Functions и в `src/`.

## Что где

| Путь | Что это |
| --- | --- |
| `samples/*.json` | Разборы образцов: макет по схеме A1 + содержимое. Форма записи — та, которую на шаге A4 будет отдавать vision-модель |
| `fonts/` | **Рабочая копия** базы шрифтов: `<id>.ttf`, `<гарнитура>.license.txt` и `roles.json` — то, что выложил `assets.mts pull` |
| `icons/` | **Рабочая копия** базы иконок: `<имя>.svg`. Нет файла — слой снимается правилом K-3 |
| `assets.mts` | Процедура заполнения баз (шаг A5): что есть, чего нет, вложить, выложить, завести заявку |
| `layouts.mts` | Сверка и синхронизация рабочей копии разборов с `card_layouts` (шаг B0) |
| `layout-tags.mts` | Офлайн-предложения тегов подбора для подтверждения в V-12 (шаг B2.0) |
| `apply-layout-tags.mts` | Запись подтверждённых B2.0 тегов в `card_layouts` |
| `render.mts` | Растеризатор: единственное место, зависящее от рантайма |
| `roundtrip.mts` | Гейт A3: разобрать → собрать → положить рядом с оригиналом |

Сама композиция считается **не здесь**, а в
[`supabase/functions/_shared/card-layout/`](../../supabase/functions/_shared/card-layout/) —
одним кодом для сервера, клиента и этих скриптов.

## Запуск

```
npm run cards:roundtrip
```

Кладёт рядом с оригиналами в `docs/assets/cardsforsysprompt/` по два файла на образец:

- `*.rebuilt.png` — наши слои **поверх оригинала**. Оригинал служит кадром вендора, поэтому
  его собственные надписи остаются на месте: разбор верен — наш текст ложится на них, промах —
  видно двоение. Проверка **попадания**.
- `*.layers.png` — те же слои **без кадра**, на фоне самого макета. Проверка **полноты**:
  видно, что в разборе есть, а чего нет.

Оба файла перезаписываются каждым прогоном и в разбор не попадают: скрипт исключает их из
списка образцов по имени.

## Библиотека макетов

**Источник правды — таблица `card_layouts` в Postgres** (миграция
`20260901120000_card_layouts.sql`); `samples/` — рабочая копия офлайн-конвейера. В отличие от
иконок и шрифтов, разборы остаются рядом с исходным содержимым: это нужно для гейта A3. После
`supabase db reset` сначала восстановите библиотеку из рабочей копии:

```
npm run cards:layouts                 что в базе есть, чего не хватает, что разошлось
npm run cards:layouts push            загрузить все проверенные разборы в базу
npm run cards:layouts pull            забрать изменения макетов базы в существующие разборы
```

`push` проверяет каждый `CardLayout`, вычисляет признак логотипа и не трогает теги подбора,
которые появятся на B2.0. `pull` намеренно не создаёт новый файл для строки, которой нет в
`samples/`: без `content` и `notes` такой файл не был бы пригодным разбором. Один разбор
`dress-summer` помечен `isFallback`: он возвращается подбором, если теги не дали совпадения.

## Теги подбора

Шаг B2.0 предлагает для каждого из 34 макетов категорию, площадку, сценарий показа и признак
скрытых кистей через Batch API. Справочники читаются из локального Supabase перед отправкой;
результат, которого нет в справочнике или чей сценарий принадлежит другой категории, не попадёт
в файл предложений. Команда **ничего не записывает в `card_layouts`**: предложения сначала
подтверждает пользователь в V-12, а несогласие исправляется одной строкой в базе.

```
npm run cards:layout-tags -- submit [layout-id…]  отправить офлайн-батч
npm run cards:layout-tags -- status                 узнать статус
npm run cards:layout-tags -- fetch                  сохранить проверенные предложения локально
npm run cards:apply-layout-tags                     записать подтверждённые предложения в базу
```

`submit` расходует средства через Batch API. Запускайте его только после явного разрешения на
платный прогон. `apply-layout-tags` запускается только после ревью и явного подтверждения
пользователя в V-12: он повторно проверяет справочники, ожидает ровно 34 предложения и обновляет
ровно одну строку на макет. Локальные файлы состояния и предложений игнорируются Git.

## Базы иконок и шрифтов

**Источник правды — таблицы в Postgres**, а не эти папки: `card_icons`, `card_font_families`,
`card_fonts`, `card_font_roles` (миграция `20260831120000_card_assets.sql`). Там дедуп по
имени и по содержимому держится ограничениями базы, а не внимательностью человека, и оттуда
же возьмёт содержимое сборщик в Edge Function. Папки рядом — **рабочая копия**: из неё
рисует офлайн-сборщик, чтобы гейт A3 гонялся без поднятой базы.

```
npm run cards:assets                 что в базах есть, чего нет, что разошлось с копией
npm run cards:assets push            вложить содержимое из папок в базу
npm run cards:assets pull            выложить содержимое базы в папки
npm run cards:assets request <имя> <описание> [из-образца]
```

Содержимое живёт в базе, а миграции его не несут — после `supabase db reset` таблицы
возвращаются с одними заявками, и содержимое возвращает `push` из рабочей копии.

**Запись заводится в два приёма.** Разбор образца (шаг A4) создаёт заявку — имя, описание,
происхождение; содержимое остаётся пустым. Человек кладёт файл в папку и запускает `push` —
та же строка становится готовой. Пока содержимого нет, слой иконки снимается правилом K-3:
текст модуля остаётся на месте, композиция держится.

**Иконка** — минимальный самодостаточный SVG, без внешних ссылок и шрифтов внутри: сборка в
сеть не ходит. В разборе иконка называется именем, а не содержимым.

**Шрифты — только со свободной коммерческой лицензией**, и лицензия хранится полем у
гарнитуры (`card_font_families.license` + полный текст `license_text`, требование OFL —
распространять его вместе с файлами). Стартовый набор: **Montserrat** (Regular / SemiBold /
Bold / Black) и **Marck Script**, обе с кириллицей, обе SIL OFL 1.1.

Переменные шрифты не годятся: `resvg` берёт у них только экземпляр по умолчанию, и
`font-weight` в SVG не действует — проверено 2026-08-31 на Montserrat[wght] и Inter[opsz,wght].
В базу кладутся **статические начертания**, по файлу на насыщенность.

Разбор называет не гарнитуру, а **роль** (`display` · `heading` · `body` · `label` ·
`accent`): по растру чужой карточки гарнитуру достоверно не восстановить и чаще всего не
лицензировать. Отображение роли в гарнитуру живёт в `card_font_roles`, а в рабочей копии —
в `fonts/roles.json`, который пишет `pull`; в коде растеризатора его нет.

**Новая гарнитура заводится миграцией, а не скриптом.** Семья, роль и лицензия — решения:
они проходят ревью в диффе. Скрипт вкладывает содержимое, но не выдаёт лицензии.

## Растеризатор

`resvg` в виде WebAssembly (`@resvg/resvg-wasm`) — один и тот же модуль в Node, Deno и
браузере, поэтому пиксели совпадают везде, а не «примерно совпадают». Обоснование выбора —
[ADR-0012](../../docs/adr/0012-card-layout-is-ours-not-vendors.md) и раздел A2 плана.

На пользовательском пути растеризатор работает в Edge Function. Его wasm и все статические
начертания из `fonts/` лежат в приватном Storage-бакете `card-render-assets`, а не в бандле
функции. После `supabase db reset` восстановите их из рабочей копии:

```
npm run cards:assets push
npm run cards:render-assets
```

Edge Function загружает `resvg/index_bg.wasm`, `fonts/manifest.json` и названные в манифесте
шрифты один раз на холодный старт; дальнейшая растеризация в сеть не ходит.
