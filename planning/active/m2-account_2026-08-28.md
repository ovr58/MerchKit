# Веха M2 — Аккаунт

Status: ACTIVE (с 2026-08-28)

## Context

M1 закрыта: сборка, тема с токенами AA, логгер, конвейер миграций и связка фронтенд ↔ Edge
Function работают, прод поднят. Продуктовых экранов нет ни одного, доменных таблиц — тоже.

M2 — первая веха с продуктом. Без пользователя не существует ни баланса, ни каталога: всё в
продукте привязано к `auth.uid()`. Она же первая, где появляется RLS — и где закладывается
единая SQL-функция условия доступа, от которой зависят все последующие таблицы
([`SPEC.md`](../../docs/SPEC.md) §4).

Границы вехи — [`00_GENERAL_PLAN.md`](../reference/00_GENERAL_PLAN.md) § M2. Макеты
утверждены заходом D1 ([V-08](../../docs/VISUALS.md#v-08)), вёрстка идёт по ним.

**Решения пользователя на старте вехи (2026-08-28):**

- Ветка `claude/m2-account` от `main`; D1 влит в `main` fast-forward'ом локально, пуш — по
  отдельной команде.
- Подтверждение email доводим **только до локального окружения** (Inbucket). Прод-SMTP —
  отдельный вопрос перед деплоем: встроенная почта Supabase на прод не годится
  (`auth.rate_limit.email_sent = 2` в час).
- **Подтверждение email закрывает вход целиком** — встроенный механизм Supabase, своё не
  пишем. Состояния «вошёл, но не подтвердил» у платформы нет: замеры и последствия —
  [ADR-0008](../../docs/adr/0008-email-confirmation-gates-sign-in.md). Отсюда: артборд
  `ProfileUnconfirmed` выведен из V-08, критерий US-02 в ТЗ переформулирован.

## Цель

Пользователь заводит аккаунт, подтверждает email, входит, восстанавливает пароль и выходит.
`profiles` живёт под RLS, чужая строка не читается на уровне БД. Экраны совпадают с
утверждёнными артбордами D1.

## Границы

**Входит:** регистрация (FR-18) · подтверждение email по ссылке · вход (FR-20) ·
восстановление пароля (FR-21, US-E7) · выход (FR-24) · `profiles` + RLS + единая функция
доступа · экран профиля с балансом (всегда 0) · роутинг и гварды · приватность (NFR-06).

**Не входит:** начисление стартовых баллов (FR-19) — требует `ledger`, приезжает на M3;
пакеты пополнения и история операций с артборда профиля — тоже M3; каталог — M4.
Начислить 120 баллов в обход журнала = написать код, который M3 сразу выбросит.

## Шаги

### 0. Расхождение в утверждённых артбордах — закрыть до вёрстки

Копирайт артбордов D1 внутренне противоречив: балансы, бейдж в шапке и строка журнала
показывают утверждённые `120`, а три текстовых блока обещают `20`.

- [x] `gen.mjs`: «20 стартовых баллов» → `120` — `SignUp` (стр. 154), `SignUpErrors` (163),
      `ConfirmEmail` (180), баннер профиля (277)
- [x] Там же: «одна пробная генерация из двух объектов» противоречит решению «максимум
      **1 объект** за генерацию» ([`TZ.md`](../../docs/TZ.md) §11). Переписать под факт:
      120 ÷ 50 = две пробные генерации по одному объекту
- [x] Перегенерировать артборды (`node docs/design/d1-account/gen.mjs`)
- [x] Канвас переиздан на тот же URL 2026-08-28 (версия `120-credits-adr-0008`), 12 артбордов
- [x] Вёрстка берёт цифры из исправленного копирайта, а не из старого

## Verification

Веха закрыта, когда:

- Критерии US-02 проходят, **кроме** начисления баллов: аккаунт создаётся при совпадении
  пароля и подтверждения; несовпадение — ошибка у поля; занятый email — понятное сообщение
  со ссылкой на вход; до перехода по ссылке вход отклоняется с пояснением про письмо
  (формулировка после [ADR-0008](../../docs/adr/0008-email-confirmation-gates-sign-in.md));
  письмо запрашивается повторно.
- Критерии US-03 проходят: верная пара пускает, неверная нет; письмо восстановления
  приходит; по ссылке пароль меняется, старый перестаёт работать.
- US-E7: ответ на запрос восстановления одинаков для существующего и несуществующего email.
- NFR-04: `select` из `profiles` с чужим `id` под чужой сессией возвращает отказ
  **в pgTAP-тесте**, а не «кнопки не видно».
- После выхода защищённые маршруты недоступны, сессия не восстанавливается по F5.
- Экраны совпадают с артбордами D1 после правки шага 0.
- `supabase db reset` накатывает миграции с нуля; `npm run build` и `npm test` зелёные.

## Открытые вопросы

- ~~**Прод-SMTP.**~~ Закрыто 2026-08-28: **Brevo**, 300 писем в сутки бессрочно — против
  6 000/мес у Mailjet, 3 000/мес у Resend и закрытого в 2025 free-плана SendGrid. Профиль
  `[remotes.production]` в `supabase/config.toml` заведён, секреты — переменные окружения
  `BREVO_*` (`.env.example`). **Осталось от пользователя:** завести аккаунт Brevo,
  подтвердить адрес отправителя, положить три переменные в `.env` и накатить
  `supabase config push --project-ref uqybgbudlnlbyarkgcwk`.
- **Переиздание канваса D1** после правки копирайта — действие наружу, идёт по команде
  пользователя (шаг 0).
