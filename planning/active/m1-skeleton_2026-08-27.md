# M1 — Каркас: рабочая сборка, конвейер миграций, связка фронтенд ↔ Edge Function

Status: ACTIVE (с 2026-08-27)

Веха M1 из [`00_GENERAL_PLAN.md`](../reference/00_GENERAL_PLAN.md). Ветка
`claude/m1-skeleton`, доверенная полоса (Claude Opus 5,
[ADR-0002](../../docs/adr/0002-trust-lane-by-model-not-host.md)).

## Context

Состояние «кода в репозитории нет» кончается здесь. Дальше каждая веха опирается на три
вещи, которых сейчас не существует: рабочую сборку фронтенда, накатываемые с нуля миграции
и доказанную связку React ↔ Edge Function. M1 не содержит ни одного экрана продукта и ни
одной доменной таблицы — только сантехника, на которой M2 начнёт с первого дня.

Дизайн D1 утверждён ([V-08](../../docs/VISUALS.md#v-08)), экономика утверждена
([V-09](../../docs/VISUALS.md#v-09)) — M1 ничего из этого не ждёт и вёрстку не блокирует.

## Решения, принятые на старте вехи

| Развилка | Выбор | Почему |
| --- | --- | --- |
| Node | **22 LTS** (`nvm install 22.20.0`), фиксируется `.nvmrc` + `engines` | На 18.12.1 (EOL) недоступны актуальные Vite и Tailwind; апгрейд всё равно пришлось бы делать, дешевле сейчас |
| React | **18.3.1** | Канон и `SPEC.md` §2 говорят React 18; переход на 19 — отдельное решение, а не побочный эффект каркаса |
| Стилизация | **Tailwind v4** через `@tailwindcss/vite` + shadcn/ui | По [`SPEC.md`](../../docs/SPEC.md) §2; конфиг Tailwind v4 — CSS-first, отдельный `tailwind.config` не заводится |
| Имя клиентского ключа | **`VITE_SUPABASE_PUBLISHABLE_KEY`** | Так уже названо в реальном `.env`; `.env.example` с `..._ANON_KEY` расходится с ним и правится под факт |
| Ветка от | `main` (доки D1/экономики влиты fast-forward) | Диф вехи — только код каркаса |

Правятся: `.env.example` (имена ключей), `README.md` (как поднять), `planning/INDEX.md`.

- [x] **7. Конвейер Supabase.** `supabase` CLI в devDependencies, `supabase init`,

- [x] **9. Тесты.** Vitest + один осмысленный тест (логгер: уровень, отсутствие вывода
      секретов). `npm test` проходит.
- [x] **10. Гигиена секретов.** `.env` не в индексе, `git log -p` и рабочее дерево без
      ключей, `.env.example` не содержит реальных значений.

### Что реально сделано (2026-08-27)

Каркас собран и закоммичен (`6569886`). Фактические отклонения от плана:

- **TanStack Query добавлен в M1**, хотя в списке вехи его не было: без него единственный
  сетевой вызов страницы упирался в предупреждение линтера про setState в эффекте, а
  библиотека всё равно зафиксирована в [`SPEC.md`](../../docs/SPEC.md) §2 и нужна с M2.
- **Палитра D1 не прошла AA по трём парам** и поднята в токенах (цифры — в шапке
  `src/index.css` и в коммите). Это дефект утверждённого канваса, а не вкус: артборды
  показывают белый текст на `#16A34A` (3.30:1) и плейсхолдер `#A1A1AA` (2.56:1).
  D1 стоит перерисовать под новые значения, иначе вёрстка M2 разойдётся с макетом.
- **Имя миграции** — `20260827000000_init.sql`, а не `0000_init.sql`: CLI требует
  временную метку. Содержимое — схема `app` под будущую единую SQL-функцию доступа.
- **Добавлен `.gitattributes`** (`eol=lf`): без него Windows-клиент писал бы CRLF и дифф
  забивался бы переводами строк.
- Линтер — `oxlint` (то, что кладёт актуальный шаблон Vite), не ESLint.

## Open questions

- **Docker установлен, но движок не стартует: на машине не было WSL 2.** Docker Desktop
  показывает «Virtualization support not detected», и это сообщение вводит в заблуждение:
  `HypervisorPresent = True`, то есть виртуализация в железе включена, а `False` в
  `VirtualizationFirmwareEnabled` — обычный артефакт уже работающего гипервизора. Реальная
  причина — отсутствие компонентов. Через DISM включены `VirtualMachinePlatform` и
  `Microsoft-Windows-Subsystem-Linux`, **требуется перезагрузка машины**, после неё —
  `wsl --update` и запуск Docker Desktop. До этого `supabase start` / `db reset` и связка
  фронтенда с `health` остаются непроверенными.
- **Секреты из `.env` агенту недоступны** (правило прав запрещает чтение файла) — и это
  правильно. Значит `supabase login` / `link` выполняет пользователь в своём терминале,
  после чего `db push` и `functions deploy` идут уже с сохранённым токеном.
- Куда деплоится фронтенд — `TODO(пользователь)` в [`SPEC.md`](../../docs/SPEC.md) §2.
  На M1 не влияет, всплывёт на M6.
