# M1 — Каркас: рабочая сборка, конвейер миграций, связка фронтенд ↔ Edge Function

Status: ACTIVE (с 2026-08-27)

Веха M1 из [`00_GENERAL_PLAN.md`](../reference/00_GENERAL_PLAN.md). Ветка
`claude/m1-skeleton`, доверенная полоса (Claude Opus 5,
[ADR-0002](../../docs/adr/0002-trust-lane-by-model-not-host.md)).

## Context

Состояние «кода в репозитории нет» кончается здесь. Дальше каждая веха опирается на три
вещи, которых сейчас не существует: рабочую сборку фронтенда, накатываемые с нуля миграции
и доказанную связку React ↔ Edge Function. M1 не содержит ни одного экрана продукта и ни
одной доменной таблицы — только сантехника, на которой M2 начнёт с первого дня.

Дизайн D1 утверждён ([V-08](../../docs/VISUALS.md#v-08)), экономика утверждена
([V-09](../../docs/VISUALS.md#v-09)) — M1 ничего из этого не ждёт и вёрстку не блокирует.

## Решения, принятые на старте вехи

| Развилка | Выбор | Почему |
| --- | --- | --- |
| Node | **22 LTS** (`nvm install 22.20.0`), фиксируется `.nvmrc` + `engines` | На 18.12.1 (EOL) недоступны актуальные Vite и Tailwind; апгрейд всё равно пришлось бы делать, дешевле сейчас |
| React | **18.3.1** | Канон и `SPEC.md` §2 говорят React 18; переход на 19 — отдельное решение, а не побочный эффект каркаса |
| Стилизация | **Tailwind v4** через `@tailwindcss/vite` + shadcn/ui | По [`SPEC.md`](../../docs/SPEC.md) §2; конфиг Tailwind v4 — CSS-first, отдельный `tailwind.config` не заводится |
| Имя клиентского ключа | **`VITE_SUPABASE_PUBLISHABLE_KEY`** | Так уже названо в реальном `.env`; `.env.example` с `..._ANON_KEY` расходится с ним и правится под факт |
| Ветка от | `main` (доки D1/экономики влиты fast-forward) | Диф вехи — только код каркаса |

## Critical files

Создаются:

- `package.json`, `vite.config.ts`, `tsconfig*.json`, `index.html`, `.nvmrc`
- `src/main.tsx`, `src/App.tsx`, `src/index.css` (токены Tailwind v4)
- `src/lib/logger.ts` — логгер проекта (NFR-10)
- `src/lib/supabase.ts` — клиент из `VITE_*`
- `src/lib/env.ts` — валидация переменных окружения на границе
- `src/lib/logger.test.ts`, `vitest.config.ts` (или секция `test` в `vite.config.ts`)
- `supabase/config.toml`, `supabase/migrations/0000_init.sql`
- `supabase/functions/health/index.ts` — пустая функция, отвечающая фронтенду
- `components.json` + `src/components/ui/button.tsx` (проверка конвейера shadcn)

Правятся: `.env.example` (имена ключей), `README.md` (как поднять), `planning/INDEX.md`.

## Шаги

- [ ] **1. Скелет Vite.** `npm create vite@latest` (react-ts) в существующий репозиторий,
      React 18.3.1, `.nvmrc` = 22, `engines.node >= 22`, скрипты `dev`/`build`/`test`/`lint`.
      Проверка: `npm run build` проходит.
- [ ] **2. Tailwind v4 + токены.** `@tailwindcss/vite`, токены темы в `src/index.css` из
      палитры D1 (`docs/design/d1-account/gen.mjs`: primary `#16A34A`, fg `#09090B`,
      muted `#F4F4F5`, border `#E4E4E7`, destructive `#EF4444`). Контраст текст/фон
      ≥ 4.5:1 посчитан и записан комментарием рядом с токенами (NFR-07).
- [ ] **3. Брейкпоинты и правило 360 px.** Контейнер приложения и заготовка раскладки:
      десктоп основной, 360 px не ломается (NFR-09). Без экранов продукта — только каркас
      страницы.
- [ ] **4. shadcn/ui.** `components.json`, одна компонента (`button`) как доказательство,
      что генератор ставит код в репозиторий и он собирается.
- [ ] **5. Логгер (NFR-10).** `src/lib/logger.ts`: уровни, структурное поле контекста
      (позже туда ляжет `generationId`), в проде — без `console.log`, без токенов и PII.
      Узкий интерфейс: `logger.info/warn/error(msg, ctx?)`.
- [ ] **6. Границы окружения.** `src/lib/env.ts` валидирует `VITE_SUPABASE_URL` и
      `VITE_SUPABASE_PUBLISHABLE_KEY` при старте и падает с внятным сообщением, а не
      `undefined` в рантайме. `.env.example` приводится к реальным именам.
- [ ] **7. Конвейер Supabase.** `supabase` CLI в devDependencies, `supabase init`,
      `supabase/migrations/0000_init.sql` (пустая/техническая миграция — доменных таблиц в
      M1 нет), `.gitignore` под `supabase/.temp`.
- [ ] **8. Пустая Edge Function.** `supabase/functions/health/index.ts` — отвечает
      `{ ok: true, ts }`, CORS для локального фронтенда; вызов из `App.tsx` через
      `supabase.functions.invoke('health')`, результат виден на экране.
- [ ] **9. Тесты.** Vitest + один осмысленный тест (логгер: уровень, отсутствие вывода
      секретов). `npm test` проходит.
- [ ] **10. Гигиена секретов.** `.env` не в индексе, `git log -p` и рабочее дерево без
      ключей, `.env.example` не содержит реальных значений.

## Verification

Соответствует критерию «Готово, когда» из генерального плана:

- `npm run build` — успешная сборка.
- `npm test` — проходит минимум один тест.
- `npm run dev` + локальный Supabase: фронтенд получает ответ от функции `health`
  (наблюдаемо на экране, не только в консоли).
- `supabase start` поднимает БД и `supabase db reset` накатывает миграции с нуля.
- `git ls-files | grep -c '^\.env$'` = 0; в `.env.example` только плейсхолдеры.
- Страница не ломается на 360 px (проверка в DevTools).

  прогон остаётся непроверенным до установки. Решение пользователя ожидается; пока Docker
  нет, эти пункты Verification помечаются как **не проверено**, а не как выполненные.
